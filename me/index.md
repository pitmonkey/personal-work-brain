# Me

The **context layer**. The rest of the store records *what you know*; this records
*who you are and how you work* — the thing an agent would otherwise make you
re-explain at the start of every session.

Each page below ships as a **template with its interview protocol embedded**.
Open one, hand it to an agent, and say *"let's do this one"* — it will run the
interview, draft the page, and ask you what it got wrong. Replace the template
body with the finished page and set `filled: true`.

## Pages

- [Identity](identity.md) — who you are in one page. **Start here.** The page an
  agent reads if it can only read one.
- [Communication style](communication-style.md) — how you write, and how you want
  things written for you. Highest immediate payoff of the four.
- [Preferences and constraints](preferences-and-constraints.md) — hard rules and
  strong opinions any agent should respect.
- [Domain knowledge](domain-knowledge.md) — what you know that a general-purpose
  model does not.

## Conventions

- **Specific, not aspirational.** Describe how you actually work, not how you wish
  you did. Confident wrong context is worse than none.
- **One page, not five.** These are read at the *start* of every task, so length
  is a running cost. Dense beats thorough.
- **Living.** A context page six months stale gives agents confident but wrong
  context. Re-run the interview when your role, stack, or priorities shift.
- **`me/` is not `decisions/`.** This section records *how you decide*; a specific
  choice is a [`Decision`](../decisions/index.md), always.
- Confidentiality applies here as everywhere — see [CLAUDE.md](../CLAUDE.md).
  These pages are the likeliest of any in the store to be pasted into a tool that
  is not yours, so keep them free of anything you would not want to travel.
